# 运行时与 PocketBase 升级决策

2026-09-09，跟踪 #14。前端开发、构建镜像和 CI 统一 Node 24 LTS，
后端模块、镜像和 CI 统一 Go 1.26。前端 PocketBase SDK 现为 0.28.0。
Node 24 的支持状态见 [Node 发布表](https://nodejs.org/en/about/previous-releases)，
Go 支持策略与版本见 [Go 发布记录](https://go.dev/doc/devel/release)。

## 分阶段迁移

1. 先统一受支持运行时，并运行现有 Go、前端和临时数据库集成测试。
   此阶段不修改 PocketBase schema，不要求迁移生产数据。
2. 从 0.21.3 升到 0.22.x 过渡线，逐版本检查迁移与 hooks。
   过渡线是迁移落脚点，不能声称它仍受长期维护或已解决全部漏洞。
3. 单独迁移到 0.23：按官方 [Go](https://pocketbase.io/v023upgrade/go/)
   和 [JSVM](https://pocketbase.io/v023upgrade/jsvm/) 指南修改自定义路由、DAO、
   hook 事件与迁移事务参数，并处理管理员身份迁移。不得仅替换 go.mod 版本。
4. 再按每个后续版本的发布说明升级至执行时最新稳定线；保持每步可以独立回滚。

每一步必须同时验证：全新数据库迁移、现有数据库副本升级、账号认证和刷新、
文件上传、relation expand、错误结构、盲校/仲裁/权限、重启持久化。
前端 SDK 升级与后端一起测试，不把“安装成功”当作兼容性证据。
保留版本化测试日志、源/目标版本及耗时。

## 数据备份和回滚点

升级前停止写入并备份完整 pb_data（数据库、上传文件及相关元数据），
记录当前镜像 digest 和配置版本；恢复到隔离实例检查完整性和文件哈希后才能升级。
每一版本保留独立备份，不覆盖前一步的恢复点。回滚时停止新服务，
恢复旧镜像和该步升级前的完整数据副本；不能让旧二进制直接打开已升级的数据目录。
本 PR 不声称已经完成生产数据副本迁移或恢复演练。

## 依赖监控

Dependabot 按前端、Go、Actions 独立每周更新；Go 仅将 patch 更新分组，
PocketBase minor 变更单独评审。每周依赖审计工作流保存 npm audit、
govulncheck 及过期版本结果；失败由 GitHub Actions 通知订阅维护者。
严重/高危可达漏洞在 24 小时内分诊，72 小时内修复或提供经过评审的缓解措施；
无法如期修复时在 issue 记录负责人、影响、缓解方式及下次复查日期。
过期提示不自动升级，也不能通过无期限忽略消除漏洞失败。

## 本次验证与数据前提

Go 1.27.0 在现有 PocketBase 0.21.3 的 JSON 路径触发递归栈溢出，
不能直接采纳仅替换镜像的升级。Go 1.26.8 的 `go test ./...`、
项目权限与上传集成通过，因此该 PR 使用 1.26 支持线。
Node 24 的前端测试和构建通过。

维护者已确认尚无正式运营数据，允许重新整理 PocketBase 数据。
后续当前版本升级可以重建 schema 和测试数据库，无需维持旧业务数据迁移兼容；
仍须验证完整功能并明确部署切换步骤，不能以空数据库启动成功代替验收。
