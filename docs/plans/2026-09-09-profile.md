# Personal profile implementation plan

**Goal:** Resolve #54 with avatar navigation, editable local nickname/email and Hinghwa profile backfill on login and binding.
**Architecture:** Extend the existing profile page. A session-authenticated endpoint accepts only name/email for the current user, validates through PocketBase and clears verification on email changes. Fetch optional public nickname/email/avatar by authenticated upstream subject after resolving the local mapping. Fill empty fields only, validate email without granting verification, and store bounded trusted-host avatar images locally. Remote email never selects a local account. Failures are independent and never prevent login; credentials and roles are not imported.
**Tech Stack:** Vue, PocketBase 0.40, Go.

1. Add `backend/profile.go` with an authenticated, bounded PATCH endpoint and validation; cover anonymous requests, identity/role injection, invalid/duplicate email, verification reset and persistence in `backend/profile_test.go`.
2. Extend `backend/hinghwa_identity.go` with bounded HTTPS public profile reads; test nickname parsing, mismatched subject, failures and preservation of local edits in `backend/external_identity_test.go`.
3. Extend `frontend/src/services/authService.js` and `views/proofreader/ProfileView.vue` with independent profile form state, errors, success and auth-store refresh. Link navbar avatar and update login copy.
4. Run frontend tests/build and backend tests, inspect the UI using mock data, update README, commit and open an independent PR against main.

No schema migration. Rollback restores code; saved profile values remain in existing user fields. Email updates require a valid session and are marked unverified; this endpoint does not verify mailbox ownership.
